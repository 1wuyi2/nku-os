## 三、任务一：实现 SLUB 分配器

### 1. 设计要求

在 uCore 中实现简化 SLUB 内存对象分配器。

采用两层内存管理结构：

第一层：通过现有 PMM 提供物理页面。

第二层：SLUB 在物理页内部划分并管理多个小对象。

SLUB 是 PMM 的上层模块，不需要将 `pmm_manager` 替换成 SLUB。

要求体现 Slab/SLUB 的主体思想，包括对象缓存、空闲对象管理、页面复用、Slab 状态转换和页面回收。

### 2. 代码组织

优先新增：

- `kern/mm/slub.c`
- `kern/mm/slub.h`

如果测试规模较大，可以新增：

- `kern/mm/slub_test.c`

若项目已有相关文件，优先沿用现有组织。

公开的早期 uCore SLUB 参考实现存在“一页一个 Slab、复用 Page 元数据”的设计，但当前项目已经使用 Page 管理连续物理页，请先分析实际字段使用情况。

允许使用独立 Slab 元数据设计，前提是保证元数据生命周期、对象对齐和 PMM 状态正确。

### 3. 必须实现的能力

实现以下功能：

**初始化**

- 初始化 SLUB 管理结构。
- 初始化不同对象大小的缓存。
- 正确设置空闲链表及缓存状态。

**对象大小分类**

建议支持：

16、32、64、128、256、512、1024、2048 字节。

对非标准大小向上匹配合适的对象类别。

支持适当的对象对齐。

**物理页管理**

- 当前缓存无可用 Slab 时，通过 `alloc_pages()` 获取页面。
- 在物理页中建立多个对象槽位。
- 记录 Slab 元数据和空闲对象链表。
- 保证元数据与对象空间不重叠。
- 不允许把页面管理元数据错误地作为用户对象返回。

**对象分配**

- 从适当缓存中选择 Slab。
- 优先复用已有空闲对象。
- 无可用对象时创建新 Slab。
- 返回有效的内核虚拟地址。
- 不允许不同活动对象发生地址重叠。

**对象释放**

- 能够定位对象所属 Slab。
- 将对象归还对应空闲链表。
- 更新已分配对象数量。
- 维护 Slab 的 full、partial、empty 状态。
- 全部对象释放后可以回收底层物理页。

为便于测试内存完全恢复，建议简化实现采用“完全空闲的 Slab 立即释放”策略。

**较大内存申请**

优先增加安全的多页分配路径，以支持超过单个对象缓存容量的请求。

需要正确保存大对象的页数及释放信息。

如果受实验架构限制而无法支持，应明确写出最大支持范围，不允许静默截断请求。

**边界处理**

正确处理：

- 0 字节请求
- 空间耗尽
- 申请大小溢出
- 无效内存分配
- 对象重复使用
- 页面归还
- 多个缓存同时工作

重复释放或无效指针不能导致静默破坏内存链表。根据当前内核约定采用断言、明确拒绝或其他合理的防护方式，并在报告说明。

### 4. 对外接口

可参考：

- `slub_init()`
- `slub_alloc(size_t size)`
- `slub_free(void *ptr)`
- `slub_check()`

最终接口名称、参数类型和实现方式应符合本仓库的编码风格。

不允许直接使用用户态 `malloc()` 或 `free()`。

如需动态管理元数据，应使用内核现有内存设施，避免 SLUB 初始化和分配过程中的递归依赖。

### 5. 正确性要求

重点确保：

1. Slab 元数据可靠。
2. 对象地址正确对齐。
3. 内存对象不发生重叠。
4. 空闲链表插入和删除正确。
5. Slab 状态转换一致。
6. 物理页面不会被重复释放。
7. SLUB 不会破坏 PMM 所维护的 `Page` 状态。
8. 每次分配和释放后计数正确。
9. 不产生不可回收的物理页泄漏。
10. 默认 Best-Fit 和可选 Buddy 分配器仍能正常运行。

完成之后，实际进行编译检查并修复编译错误。

## 四、任务二：设计并实现 SLUB 自定义测试

请为 SLUB 编写充分的内核级测试，而非简单检查返回指针是否为空。

所有测试应在 QEMU 运行的真实 uCore 内核中执行。

### 1. 测试内容

至少设计以下九组测试：

**测试一：初始化**

确认缓存正常建立，各链表和统计信息初始化正确。

**测试二：16 字节对象**

连续申请八个 16 字节对象。

验证对象地址不同、互不重叠，且能够容纳在同一个 Slab 物理页中。

**测试三：多种大小申请**

测试 16、32、64、128、256、512、1024、2048 字节申请。

额外测试 20、100、300 等非标准大小，验证对象类别选择和对齐。

**测试四：数据隔离**

向不同对象中写入不同字节模式，重新逐一读取验证。

确认对象之间没有错误覆盖。

**测试五：释放与复用**

申请多个对象后释放部分对象，再次申请。

验证已释放的对象槽位能够复用，其他对象数据保持不变。

**测试六：跨 Slab 分配**

持续分配小对象，直到单个 Slab 容量不足。

验证自动获取新的物理页，并正确管理多个 Slab。

**测试七：边界条件**

测试 0 字节、最大支持大小、超大请求、整数溢出及内存不足。

对于预期失败的申请，验证其没有破坏缓存状态。

**测试八：完整回收**

记录测试开始前的 `nr_free_pages()`。

释放所有测试对象，检查全部 Slab 清理完成，并确认空闲物理页数恢复至测试前。

**测试九：混合压力测试**

使用固定随机种子进行至少 500 次分配与释放混合操作。

每次操作检查：

- 地址有效性
- 对齐
- 活动对象不重叠
- 数据完整性
- 缓存状态一致性
- 必要的空闲页计数

测试结束时释放全部对象并重新检查内存恢复。

如实现了大对象多页分配，也必须加入对应的申请、写入与释放测试。

### 2. 测试接入

优先使用 `SLUB_SELFTEST` 编译宏控制测试运行。

默认配置不得强制执行 SLUB 测试，以免影响官方评分。

### 3. 输出要求

`[SLUB Test 1] Initialization: PASS`

`[SLUB] ALL TESTS PASSED`

### 2. 实际调试过程

请在合适的断点完成以下工作：

1. 读取 `satp` 寄存器。
2. 检查 MODE，确认是否为 Sv39。
3. 计算根页表物理地址。
4. 选择一个已经建立映射的内核虚拟地址。
5. 将其拆分为 VPN[2]、VPN[1]、VPN[0] 和页内偏移。
6. 读取根页表中的对应 PTE。
7. 解释 PTE 的有效位、权限位和物理页号。
8. 如果当前 PTE 指向下一级页表，继续读取下一级。
9. 逐级查找直到遇到有效叶子 PTE。
10. 根据叶子层级计算最终物理地址。
11. 通过 GDB 或 QEMU monitor 验证地址转换结果。

必须正确处理 Sv39 中可能存在的超级页映射，不能假设每个地址都一定访问三级页表。

检查 PTE 的 V、R、W、X 等关键位及合法性。
