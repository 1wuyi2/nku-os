## 一、实验目的

本实验的主要目的是：

1. 理解 RISC-V Sv39 页表的建立、开启和使用过程，理解虚拟地址到物理地址的映射关系。
2. 理解操作系统如何通过 DTB 获取物理内存信息，并利用 `Page` 描述符、空闲链表等数据结构建立物理内存管理机制。
3. 理解连续物理页的分配与释放过程，在已有 First-Fit 实现的基础上完成 Best-Fit 页面分配算法。
4. 学习使用 GDB、QEMU、`make grade` 和 Git 对操作系统内存管理代码进行调试、验证和协作开发。
5. 在 AI 辅助开发过程中，通过编写 spec 和 prompt、检查生成代码、定位错误并迭代修正，加深对内存管理核心代码的理解。

## 三、实验整体逻辑分析

### 3.1 本章节的逻辑主线

Lab1 解决的是“让最小 uCore 内核启动起来”，Lab2 则进一步解决“内核启动以后如何建立地址映射，并有效管理机器上的物理内存”。本实验的整体逻辑可以概括为：

```text
QEMU / OpenSBI 启动
        ↓
entry.S 保存 hartid 与 DTB 地址
        ↓
建立启动页表并开启 Sv39
        ↓
进入高地址映射后的 kern_init()
        ↓
dtb_init() 解析物理内存范围
        ↓
pmm_init()
        ↓
page_init() 建立 Page 描述符数组和初始空闲页区间
        ↓
pmm_manager 管理物理页
        ↓
Best-Fit 完成连续物理页的分配与释放
        ↓
check / make grade 验证实现
```

本章的核心不只是“写一个页面分配算法”，而是把**页表、虚拟地址、物理地址、设备树、Page 描述符、空闲链表和页面分配器**连接成一套完整的物理内存管理流程。

### 3.2 功能的逐步实现

1. 首先在 `entry.S` 中建立启动页表并开启 Sv39，使内核能够按照链接时使用的高虚拟地址继续运行。
2. 随后通过 OpenSBI 传入的 DTB 地址获取物理内存的起始位置和容量，为后续内存管理确定边界。
3. 在 `pmm.c` 中完成物理页初始化：计算可管理的页号范围、建立 `Page` 描述符数组、标记已占用区域，并把剩余完整物理页交给物理内存管理器。
4. 在统一的 `pmm_manager` 接口之上实现 Best-Fit 页面分配器，包括初始化、分配、释放、空闲块分割和相邻块合并。
5. 最后通过框架自带的检查函数、QEMU 运行结果和 `make grade` 对 Page Init 与 Best-Fit 两部分进行验证。

### 3.3 Lab2 中的关键数据结构与关系

后期结合最终代码补充以下内容：

- `struct Page`：每个物理页对应的描述符。
- `free_area_t`：维护空闲页块链表和空闲页总数。
- `page_link`：将空闲块头部的 `Page` 接入双向链表。
- `property`：记录一个空闲连续页块包含的页数。
- `PG_reserved` / `PG_property`：描述物理页当前状态。
- `pmm_manager`：通过函数指针统一抽象不同页面分配算法。
- `pages`、`npage`、`nbase`、`va_pa_offset`：建立物理页、Page 描述符及虚实地址转换之间的联系。
